## 5. 功能与交互方案

### 5.1 树行直接编辑

- 左键点击 key/value 进入行内编辑，默认显示态没有输入框边框；聚焦后显示清晰边框。
- Enter 提交、Escape 取消；Tab 提交并进入下一可编辑字段；失焦尝试提交，失败保留草稿并显示短错误，避免静默丢弃。
- key 只允许对象成员编辑；数组索引只读，根显示 `$`，不可改名。
- 中文 IME 组合输入不触发 Enter 提交；确认提交后才向统一命令链写入，不能每个按键生成历史记录。
- 从完整源文本读取值，不能用截断 preview 提交。长字符串可用锚定在该行的多行浮层编辑，不恢复底部常驻表单；超过现有限制则提供转入代码编辑入口。
- 编辑中的行固定节点身份，避免滚动虚拟化或 Worker 更新覆盖草稿；必要时把草稿保存到独立编辑会话，而非仅存在行组件 state。
- 提交捕获基准 revision，过期则明确提示并保留草稿。树过期、重复 key、大文件限制、后台失败时继续沿用现有编辑门禁。
- 每次有效提交是一条可撤销事务，文本和树一起更新，不另设一份可写 JSON 数据副本。

### 5.2 自动与字符串模式

JSON 只有 object/array/string/number/boolean/null 六种实际类型。“自动”是输入策略，不写入 JSON 的类型信息。

建议自动模式规则：

| 输入                    | 保存结果                                                   |
| ----------------------- | ---------------------------------------------------------- |
| `123`、`-1.2`、`1e3`    | JSON 数字，保留原字面量，不经 JS Number 往返               |
| `true` / `false`        | 布尔值，仅接受小写精确匹配                                 |
| `null`                  | null；与现有六类型支持一致                                 |
| 普通文字、`001`、空输入 | 字符串，空输入保存为 `""`                                  |
| `{...}`、`[...]`        | 默认按字符串处理；创建结构通过类型菜单，避免粘贴误改变层级 |

数字匹配 JSON 完整数字语法，不使用 parseFloat。推断可检测去除首尾空白后的数字/布尔/null；回落字符串时保留用户输入的原空白。字符串模式下所有输入按原文本转义并加引号，`123` 保存为 `"123"`，输入框不要求用户手写 JSON 引号。

类型提示同时表达输入策略与实际类型：自动模式小图标附实际类型 tooltip，强制字符串用不同图标/状态；数字用 # 风格图形，布尔/null 用紧凑图形。手柄和类型图标默认分开，拖动能力持续可见，不靠 hover 替换唯一入口。

切换“字符串”对标量保留可见内容并加引号，字符串自身不重复编码；对象/数组转字符串使用其完整 JSON 文本作为字符串内容，不丢失数据。切回自动按规则重判标量内容。容器保持容器结构，标量编辑才应用自动推断。

### 5.3 行首手柄与右键菜单

- 每行头部放置拖动手柄；左键按住超过小位移阈值才拖动，编辑字段与展开按钮不会启动拖放。
- 右键手柄选中该节点并显示菜单，屏蔽该处原生菜单；键盘 Shift+F10 或菜单键也可打开。根节点保留菜单入口，但禁用拖动和不适用操作。
- 拖动目标明确区分同级插入线与容器内部高亮，支持边缘自动滚动。继续禁止拖入自身/后代，并在落点与提交两处校验。
- 菜单放在 Portal，靠窗口边缘自动翻转和限制高度。Esc/外部点击关闭并恢复焦点；方向键与 Enter 可操作；类型子菜单通过点击展开，也支持键盘左右键。

```text
类型                 ▸ 自动 / 字符串 / 数组 / 对象
添加子节点             仅对象、数组可用
追加                   同级下方
插入                   同级上方
复制                   深复制到同级下方
移除
────────────────────
更多                 ▸ 排序、移动、转到代码
```

按需求将“类型”作为唯一类型子菜单入口；追加、插入、复制、移除保持一级动作。现有排序和精确移动能力迁入“更多”弹层，不占树底部空间。“转到代码”作为按需功能，不再显示常驻“定位文本”按钮。

### 5.4 空节点与转换

- 新增节点默认为自动模式、实际值 `""`。对象使用唯一默认 key `key`、`key1`、`key2`…，立即聚焦 key；数组新增 `""` 并聚焦 value。
- 数组转换结果为 `[""]`；对象转换结果为 `{ "key": "" }`。这是可直接保存的合法 JSON，输入框用 placeholder 提示待填。
- 选择数组或对象将清空原内容并生成上述一个空子节点，展开该容器并聚焦子节点。转换与空子节点创建合为一条历史记录。
- 重新选择当前容器类型默认只表示保留类型，不隐式清空已有容器；确需重置通过明确动作，避免点击当前类型造成意外丢失。
- 根也允许类型转换；根的插入、追加、复制、移除不可用。空文档保留代码输入入口，并提供简洁“创建对象/数组”入口，避免没有合法根时无法开始。

### 5.5 插入、复制与冲突

- 追加/插入相对节点在父容器中的实际位置计算，展开状态不影响语义；容器增加子项默认加在末尾。
- 复制包含整个后代子树，数组重新计算索引；对象保持 key，发生冲突后用尾缀数字寻找第一个可用名：`name` → `name1` → `name2`。
- 读取和复制原始数字字面量，避免 JSON.parse/stringify 整树导致大整数精度损失。复制产生全新节点 ID，并复制对应输入模式。
- 改 key 或跨对象移动若冲突，保留现有拒绝与提示行为；只有新增默认名、复制才自动生成唯一 key，避免隐式改写用户手输名称。
- 删除、复制、移动、插入、类型转换都必须一次撤销；撤销恢复数据、节点身份及类型模式。大规模操作继续执行现有文本、深度、节点数限制。

### 5.6 字符串模式跨保存记忆

该模式不能仅从 JSON 推导，不能把状态直接塞入 JSON 文件。建议增加独立的模式存储服务：

1. 会话内按 documentId + 稳定 nodeId 管理模式；模式变化即使不改变 JSON 文本，也要进入统一历史。
2. 文件保存成功后，将模式映射到 JSON Pointer，与文件身份、结构指纹、元数据 schemaVersion 一起写入应用 userData 下的本地元数据文件。
3. 重命名、移动、排序后由命令和身份映射更新路径；删除清除相关记录，复制继承模式，撤销恢复模式。不能只用数组索引长期绑定。
4. 重开文件验证文件身份与内容/结构指纹后恢复；仅修改空白且结构和值一致时可恢复。外部修改导致对应关系不可靠时丢弃无法确定的记录，给一次简短提示，不把锁定状态套到错误节点。
5. 无元数据的新文件，容器保留实际类型；已有字符串默认字符串模式，数字/布尔/null 默认自动。用户新建节点始终自动。
6. 另存为将当前模式复制给新文件身份；失败或取消不能错误迁移元数据。正常保存即使 JSON 无变化也应确保模式持久化。
7. 元数据原子写入，不保存完整 JSON 内容。设置容量与过期清理策略；具体阈值实施时定稿。通过主进程已有边界访问，不给渲染进程新增任意文件访问能力。
8. 模式是本机应用状态，单独把 JSON 文件发往另一台电脑不会携带模式。未保存新文档仍沿用现有不提供崩溃恢复的边界。

### 核心命令接口

所有命令继续通过 `TreeCommand → TextDocumentSession → Worker/JsonDocumentEngine → 源码范围编辑 → Monaco 统一历史` 执行。

| 命令      | 参数与语义                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| `add`     | `nodeId` 为目标容器；可选 `index` 为从 0 开始的子节点位置，省略则末尾追加；可选 `key` / `valueText` / `valueType` |
| `insert`  | `nodeId` 为参照节点；`position: 'before' / 'after'` 表示同级上插/下加；可选 `key` / `valueText` / `valueType`     |
| `copy`    | `nodeId` 为源节点；在同级下方深复制完整子树，对象 key 自动消除冲突                                                |
| `convert` | `nodeId` 为转换节点；`valueType: 'array' / 'object'` 一次清空原内容并产生一个空子节点                             |

示例：

```ts
// 在容器第一个位置加入空节点。
{ kind: 'add', nodeId: containerId, index: 0 }
// 在参照节点下方加入同级空节点。
{ kind: 'insert', nodeId: referenceId, position: 'after' }
// 深复制至当前节点下方。
{ kind: 'copy', nodeId: sourceId }
// 转换为带一个空子节点的数组。
{ kind: 'convert', nodeId: targetId, valueType: 'array' }
```

### 行为与实现

- `src/core/commands/insertion-commands.ts` 集中处理唯一 key、子树节点计数、容量门禁与单次成员插入；`tree-commands.ts` 扩展命令并统一校验预测结果。
- 新增的默认值是合法 JSON 字符串 `""`；对象默认名为首个可用的 `key`、`key1`、`key2`…。“自动”模式的会话/持久化元数据属于阶段 4，本阶段不声称已实现该模式。
- 复制默认以原 key 为基础寻找第一个可用数字尾缀，例如已有 `name`、`name1` 时生成 `name2`。显式指定 key、改名或移动冲突仍拒绝，不静默改写用户名称；空 key、Unicode 转义同名与 `__proto__` 均按普通属性处理。
- 新增/插入/复制使用原源码范围定位，保留既有成员和所有数值字面量；深复制直接复制完整值源码，不对整个对象执行 JSON.parse/stringify 往返。
- 新增与复制生成全新节点 ID；原节点及其后代/同级 ID 保持。转换保留当前节点 ID，原后代移除，新空子节点获得新 ID。
- 转换数组输出 `[""]`，转换对象输出 `{"key": ""}`；转换及空节点创建合为单次源码编辑。重复选择当前容器类型是无操作，不清空原有内容，也不创建历史记录。
- 根可转换、根容器可加子节点；根的同级插入/复制拒绝。位置必须是安全整数，范围为 0 到当前子节点数（含末尾）。
- 新增/插入/复制/转换在提交前检查 100,000 个树节点上限；文本预测长度超过 20 Mi UTF-16 字符或结构超过 512 层时拒绝。容量已满时仍允许转换大子树以减少节点数。
- 新命令沿用文档 ID、revision、原文一致性、重复 key、忙碌/IME/过期树门禁。每条有效新命令返回一次源码编辑，并由会话单次调用 `applyEdits`，沿用 Monaco 已有事务边界；撤销/重做恢复精确原文及历史节点 ID。
- JSON Worker 增加稳定名称 `json-document`，便于运行诊断及真实打包 Worker 回归识别，没有新增对渲染进程暴露的 API。

### 模式规则与命令

- `edit-modes.ts` 集中定义 `auto` / `string` 输入策略。自动模式仅对完整 JSON 数字、小写 `true` / `false` / `null` 推断；保留数字字面量，不经 JS Number 往返。其他输入保留原文本并转义为字符串，包含空输入、`001` 和容器文本。
- `set-mode` 切换模式并在必要时转换值；字符串不重复编码，对象/数组切到字符串保留完整源码。`edit-value` 接收不带 JSON 引号的用户文本，按节点模式编译源码编辑，供阶段 5 使用。现有“节点 JSON 值”仍是直接编辑 JSON 源码的入口。
- 已有 JSON 字符串默认锁定字符串；其他实际类型默认自动。新增默认节点、转换生成的空子节点采用自动；显式选择字符串类型仍锁定字符串。
- 稳定节点 ID 负责会话内继承模式；重命名、移动、排序保持模式，深复制继承整棵子树的模式，删除移除模式。持久化和历史快照只保存偏离默认值的“自动字符串”，避免给普通数字或锁定字符串存冗余记录。

### 统一历史与保存

- 文本变更继续使用 Monaco 原生编辑事务；只改变模式、不改变源码时也产生一条事务并标记文档已修改。该事务通过 Monaco 的资源撤销服务加入同一个历史栈，原生 Ctrl+Z/Ctrl+Y 与工具栏撤销/重做均可使用。
- `ModeTimeline` 区分相同原生文本版本下的模式历史，并记录 JSON Pointer 快照。恢复不依赖 Worker 的 8 个身份检查点；超过该缓存后仍可恢复模式。相同快照复用数组，随编辑器实例销毁释放。
- 保存等待当前验证与模式导出，并检查文档版本，防止把旧文本与新模式组合保存。模式写入失败时 JSON 文件已正常保存，状态提示失败，保留未保存标记以便重试；关闭流程仍检查未保存状态。
- 初始化 Monaco 时明确采用输入文本的 LF/CRLF，修复 Windows 打开无换行的 LF 文本后，首次格式化被编辑器默认 CRLF 转换而导致事务校验失败的问题。编辑器使用的 Monaco 服务在首个实例创建前注册，重开文件不会出现服务缺失错误。

### 本地元数据边界

- 主进程 `NodeModeStore` 使用 `userData/node-edit-modes.json`，schema 版本为 1。保存规范路径的 SHA-256 身份、忽略空白的 JSON token 指纹、更新时间和稀疏模式路径；不保存完整 JSON 内容或值。
- 文件身份来自现有 FileService 授权和规范路径。仅扩展已有打开/保存请求的可选字段；没有新增 IPC 通道、桌面 API 方法或渲染进程任意路径访问能力，额外字段和无效快照仍拒绝。
- 先完成 JSON 原子保存，再通过串行队列原子写模式。另存为创建新文件身份的模式记录，保留原文件记录；取消另存为不迁移模式。
- 重开时仅在身份和指纹匹配后恢复。仅修改空白可恢复；修改值、成员顺序、数字或字符串源码字面量则保守失效并提示。记录缺失或过期时采用默认模式；损坏、不可读记录给出简短提示。
- 存储上限：100 个文件、8 MiB、90 天；快照最多 100,000 项、序列化长度最多 4 Mi UTF-16 字符，单个 Pointer 最多 65,536 字符。写入时清理过期和较旧记录。元数据文件拒绝符号链接、目录与超限内容。

模式属于本机应用状态，单独复制 JSON 到其他电脑不会携带模式。Monaco 资源撤销桥接依赖锁定的 0.57.0 内部接口，升级时必须复测混合文本/模式历史；渲染进程快照按编辑器生命周期保留，本轮未进行长时间历史内存压力测试。

### 编辑与提交

- 对象属性名和标量值改为无边框按钮，点击或键盘激活即可编辑；根名称、数组索引和容器摘要保持显示态。字段与展开按钮独立，不作为拖动入口。
- 短文本在原字段位置编辑，长于 120 字符或包含换行时打开多行浮层。输入值读取完整源码并解码字符串，不使用截断的 preview；字符串模式不要求用户手写 JSON 引号，数字保留字面量精度。

### 草稿与浮层生命周期

- 草稿捕获文档身份、节点 ID、revision、原值与输入模式。树过期、revision 变化、节点身份被后台重建或节点被删除时，保留已修改文本并拒绝旧基准提交；取消后可依据最新内容重新编辑。
- 后台重启导致节点 ID 重建时，未修改的输入框自动结束；有修改的草稿继续保留。切换到其他文档时清除旧文档编辑会话，不向新文件套用草稿。

### 树行与菜单

- 所有节点持续显示行首手柄。普通节点左键按住拖动，右键选中并打开菜单；根节点及只读节点保留菜单入口、禁用拖动。手柄获得键盘焦点后 Enter/Space 可打开菜单；树行通过方向键获得焦点后，也支持 Shift+F10 和菜单键。
- 原先占宽度的 `number` / `string` 等文字改为本地 SVG：自动字符串、锁定字符串、数字、布尔/null、数组、对象各有紧凑提示。tooltip 与可访问名称补充输入模式和实际类型；手柄不被类型图标替换。
